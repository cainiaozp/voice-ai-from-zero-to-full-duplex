# 10课学习验收与正式全双工系统验收

## 模型原理部分

| 课 | 验收问题 | 可观察证据 |
|---|---|---|
| 01 | 16000点波形为什么变成98个STFT时间窗？ | `fft.png`、Log-Mel shape |
| 02 | 模型根据频率还是时频顺序分类？ | AudioCNN confusion matrix |
| 03 | Cross Attention 的 Q 与 K/V 来自哪里？ | attention `[L,T]` |
| 04 | 为什么保留 ID 还能恢复音频？ | 多阶段 RVQ codes 与声音 |
| 05 | 缺相位如何影响重建？ | Griffin–Lim 试听与对比图 |
| 06 | 为什么 Flow 推理不需要真实目标 x1？ | 训练与推理速度场轨迹 |
| 07 | 为什么每80ms有多个码本 ID？ | `[T,16]` 码本矩阵 |
| 08 | 为什么 VAD 的静音不能代替话轮结束？ | 固定超时的 false cutoff |

| 10 | 打断为什么要清理 GPU/服务端/客户端？ | generation_id 及日志 |

## 真实服务级别验收（需另外部署真实模型）

1. 真实用户连续说话和中途停顿能保持同一对话状态。
2. AI 生成输出期间麦克风仍活跃，明确打断能停止**浏览器实际播放**的旧音频。
3. 统计从用户实际说完到第一次可听输出的 P50/P95/P99，按 Gateway、GPU、网络、播放端拆开。
4. 同步测 GPU 显存/KV 占用、解码队列、缓冲欠载、丢包、会话重连情况。
5. 测至少30分钟长会话和多会话并发，确认 Ring/窗口上下文、内存上限、摘要/恢复策略。
6. 遇到音频权限被拒绝、用户静音、回声、背景噪声、突然断网等情况时仍可恢复。

**不接受的“通过”证据**：仅凭 toy 的训练 Loss 下降、虚拟时钟中280ms的设置、GPU 0% 利用率或静态截图来宣布生产性能达标。
